## What is in the promoted model

### Architecture
- **Stage 1** `logs/beat_classifier/version_4` — decides *when* notes happen (per-slot probability,
  two channels, one per hand).
- **Stage 2** `logs/layout_phrase/version_10` — decides *what* each note is (position, direction),
  phrase-at-a-time with ctx16 + song memory.
- Decode: `section_gate="loud_only"`, temperature 0.9, top-p 0.97.
- Demucs `htdemucs` for stems; librosa for onsets.

### The eight promoted defaults

| default | value | what it does | evidence |
|---|---|---|---|
| `BEAT_TEMPO_FIT` | `1` | fits tempo+phase to detected beat positions instead of trusting `detect_bpm` | exact on 21/23 songs vs librosa's 1/23; `alignment_gap` 5.41 → 0.554 |
| `BEAT_DIFFICULTY_SCALE` | `0.48` | total note budget | **must** ship with tempo-fit — it changes slots/second; 0.55 was fitted to the wrong grid |
| `DENSITY_SELECT` | `1` | per-window budget ∝ (window prob)^γ | density_corr ~0 → 0.41+; makes density breathe |
| `DENSITY_SELECT_GAMMA` | `2.5` | γ above | sweep winner 2026-06-30 |
| `BEAT_HAND_LEAD` | `0.14` | one hand carries more of a passage, then they swap | Kyle: *"a giant difference maker… noticeably great impact on the flow"* |
| `BEAT_TRIM_TAIL` | `0.5` | no notes >0.5 s after the last musical onset | post-music notes 37.5% → ~11% of maps; 1f8d6 11 notes → 1; costs nothing over 3 seeds |
| `BEAT_ONSET_EVIDENCE` | `0.3` | window budget weighted by **audio** onset density, not model confidence | rhythm improves resolvably ⚠️see caveats |
| `BEAT_REACH` | `3:0.3:0.5` | eases transitions that are far (≥3 units) **and** soon (≤0.3 s) | `hard_rate` 0.123 → **0.0590** = human 0.0592, with **no** loss of reach distance |

Every one remains env-overridable; set it to its old value to disable.

## How we got here — the load-bearing discoveries

Chronological, with the ones that changed direction marked ★.

1. **Stage-2 layout collapse was a 1-line decode bug** (off-by-`ctx_n`), not a model failure.
2. **Density was flat because of post-processing**, not the model — the oracle-ceiling PoC showed the
   structure was latent in Stage-1 probabilities. → `DENSITY_SELECT`.
3. ★ **The eval suite was saturated** — `h_dist` ranked our maps *ahead* of humans, and a shuffled map
   scored like a human. Rebuilt as the v2 six-axis suite scored by **cohort shift + spread**, never
   per-map distance-to-median.
4. ★ **The suite was audio-blind** — five axes passed while sharing an audible defect, because none
   of them loaded the audio. → axis A8 alignment.
5. ★ **The note grid was built on a tempo wrong on 20 of 21 songs.** `detect_bpm` discarded librosa's
   beat *positions* and anchored at t=0. → `BEAT_TEMPO_FIT`. Kyle: *"genuinely beautiful… the
   foundation is now complete."*
6. ★ **The seed lottery: nothing was ever seeded.** Five runs of a byte-identical config scored
   4/2/1/3/5 of six axes. Both the decode (`torch.multinomial`) and post-processing (`random.shuffle`
   choosing *which notes to delete*) drew from unseeded global RNGs. → `--seed` / `BSA_SEED`,
   `eval_sweep --seeds N`.
7. ★ **Three numbers the suite depended on were measurement artifacts** — see landmines.
8. ★ **K2 was reframed by Kyle from diagonals to reachability**, and the measurement agreed with him
   completely: diagonals are blameless, and the diagonal-thinning lever moved `hard_rate` by exactly
   0.000. → `BEAT_REACH`.

## 🔴 Landmines — each cost real time at least once

**Loaders that silently read the wrong thing** (all three corrupted human calibrations in one session):
1. `scorecard._load_any` / `_load_notes_with_direction` **prefer ExpertPlus** — they match
   `startswith("expert")`, which `ExpertPlus*.dat` also passes, and fall back ExpertPlus-first.
   **Never calibrate the human corpus through it**; use `calibrate_playfeel.load_expert_only`.
2. **`"BPMInfo.dat".endswith("info.dat")` is `True`**, and 73 of 300 corpus zips list it first. It has
   no bpm field, so tempo silently defaulted to **120** and every note time stretched by
   `real_bpm/120`. Fixed in all six calibrators by matching the exact basename.
3. **Demucs was never seeded** — it applies random shift augmentation, so the same file gave 3649 /
   3711 / 3736 / 3777 union onsets across four runs. Seeded, it is bit-identical. Both cache builders
   now seed (`DEMUCS_SEED = 0`). ⚠️`outputs/onset_cache/` is still one *unseeded* draw, so every
   absolute A8 number carries an unquantified ±3% uncertainty.

**Others:**
- `scripts/generate.py` takes `audio` as a **positional** arg.
- Load beat checkpoints with `strict=False`.
- **Never pick inference checkpoints by `val_token_acc` / `val_f1_avg_tol`** — they anti-correlate
  with alignment and structure quality.
- **The single-song probe trap** — 1f333/*Hunger* is half-tempo and beat-domain metrics lie there.
  This has caught three hypotheses. Validate on all 24 songs.
- **Levers must go in `generate_v7_level`, not `predict_onsets`** — the latter is only called by the
  legacy `generate_level`, so a lever there is a silent no-op. This is how `BEAT_GRID_SUBDIV` died.
- **Energy is not a proxy for "the music stopped"** — 1f8d6's RMS runs 4.7 s past its last onset.
- `pgrep -f <name>` inside a shell script matches its own command line.
- `outputs/` and `data/` are gitignored. Calibration references are snapshotted to
  `docs/eval_references/` — **a copy, not the live path; re-copy whenever one changes.**

## Explicitly dead — do not revisit
| thing | why |
|---|---|
| Scratch mel transformer, Δt tokens, `phrase_energy_alpha` | superseded by MERT + explicit two-stage timing |
| `BEAT_IOI_PRIOR` as a density lever | measured negative at 3 seeds; wrecks 3 axes |
| `BEAT_GRID_SUBDIV` | no-op on the v7 path |
| Tuning anti-repeat / `dir_entropy` upward | "more diversity = more human" is false — it *caused* K2 |
| Near-integer BPM as an ArcViewer crash cause | falsified; it was in-process GTK |
| **Global diagonal thinning as a playability fix** | moved `hard_rate` by exactly 0.000 — kept only as a UI style knob |
| **Piecewise tempo / BPM events for end-of-song drift** | no offset ramp exists; it is a note-*selection* defect |

## ⚠️ Known weaknesses of this baseline
Full detail and action items in `TODO.md`. In Kyle's order of annoyance:

1. **The model does not find the core tempo-carrying instrument.** SO TIRED ROCK's dooming bass,
   Digital Life Hacker's chant pulse — notes go to "all the other little sounds" instead.
2. **Fallen Kingdom is too empty** — we play 1 note for every 2–3 of an obvious slow beat.
3. **Intensity is misallocated** — some passages play harder than the drop they surround.
4. **Phrases are not respected** — notes stop while a singer is still finishing a line.
5. **Doubles / distinct-time diversity** — 66% vs human 14%; root cause is Stage-1 handing both hands
   near-identical signal (correlation 0.985–0.993).
6. **Dot (any-direction) blocks are used decoratively** rather than for their two real purposes.
